## Код

- Сначала определяю тип репозитория: для Arcadia использую `arc`, для Git — `git`.
- Коммиты: английский язык, одна строка, нижний регистр, без co-author.
- Код пишу без комментариев, если пользователь явно их не запросил.
- Python-константы называю без начального `_`.
- Тикет или issue решаю в отдельной ветке с именем, равным номеру issue.
- Inline code в Tracker оформляю без пробелов внутри обратных кавычек: `code`.
- При наличии `Makefile` использую его подходящие цели вместо прямого запуска инструментов.
- Всё на GitHub пишу по-английски.
- Исправляю первопричину, а не симптом.
- При работае с github используй соответсвующий mcp а не CLI gh.
- Если я говорю "закомит", то только закомить; если я говорю "запуш", то только запуш; если я говорю "залей" то сначала закомить и затем запуш.
- release notes для Github Releases публикуй через gh.
- для того чтобы изучить тасклет используй `ya tool tasklet`, не пытайся ходить через API
- если есть выбор решить одну и ту же задачу через mcp или скилл, используй mcp (например для работы с trakcer)
- В PR в Arcanum если есть связный тикет то линкой его в начале перед названием PR в квадратных скобках. Например: "[SS-21365] Resume Ozon feedback imports from heartbeat checkpoints"

## Основные правила работы агента

- Довожу задачу до результата, а не останавливаюсь на плане; если заблокирован, точно называю причину и недостающие данные.
- Соблюдаю применимые AGENTS.md: учитываю область действия файла и более конкретные правила во вложенных каталогах; прямые инструкции пользователя имеют приоритет над файлами.
- Проверяю изменения подходящими тестами, сборкой или линтером; сообщаю, что проверено, а что не удалось проверить.
- Исправляю первопричину, сохраняю стиль проекта и не меняю посторонний код.
- Перед группой действий кратко сообщаю намерение, а при долгой работе — существенный прогресс; итог даю коротко, с результатом и ограничениями.
- Не коммичу, не пушу и не создаю ветки без запроса; соблюдаю разрешённый объём действий и ограничения доступа.

## KIT backend-go preset (Pi)

При работе с backend Яндекс KIT (`yastore/backend/` в основном Arc mount или любом worktree) используй канонический preset `/Users/antonmoss/arcadia/ai/artifacts/presets/kit/backend-go.yaml`.
Его skills подключены через `~/.pi/agent/settings.json`; загружай нужный `SKILL.md` перед соответствующей задачей. KIT-специфичные инструкции не применяй к посторонним проектам.

Полные тексты rules автоматически добавляет глобальное расширение `extensions/kit-backend-rules.ts` в секцию `kit_backend_go_rules` перед запуском агента в настроенных каталогах yastore, включая worktrees. Конфигурация: `~/.pi/agent/kit-backend-rules.json`; файлы: `~/.pi/agent/rules/kit-backend-go/`. Учитывай `paths` каждого правила. Команда `/kit-rules` показывает активный набор.

Локальные `AGENTS.md` также обязательны. Перед коммитом используй применимый `check-changed` и Make targets, проверяй diff после автофиксов. При блокировке проверки явно сообщай причину; не считай ручное чтение rules эквивалентом установленным hooks.
AISuite hooks `restrict_git`, `restrict_search`, `aisuite_check` этим подключением НЕ установлены в Pi. Соблюдай запрет git в Arcadia и широких поисков как инструкции; не заявляй о программной блокировке.
