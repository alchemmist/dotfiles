# Go style

Правила написания Go-кода в `backend/`. В конце каждого пункта в скобках — имя линтера, который это проверяет.

## Пробелы и переносы

- Соблюдай ограничение длины строки. В многострочной сигнатуре каждый аргумент размещай на отдельной строке; не объединяй несколько аргументов в одной строке. Закрывающую `)` размещай на отдельной строке (longlines).
- Вызов функции оформляй одним из трёх способов:

  ```go
  // целиком в одну строку, если не превышает ограничение длины
  row := r.pgxWrapper.Conn().QueryRowOnMaster(ctx, query, item.ID)

  // каждый аргумент на отдельной строке
  row := r.pgxWrapper.Conn().QueryRowOnMaster(
      ctx,
      query,
      item.ID,
  )

  // все аргументы вместе на следующей строке после открывающей скобки
  row := r.pgxWrapper.Conn().QueryRowOnMaster(
      ctx, query, item.ID,
  )
  ```

- Не оставляй первый аргумент рядом с открывающей скобкой, если остальные аргументы перенесены на следующие строки.
- Перед `return` пустая строка, кроме случая, когда `return` — первая/единственная строка блока (nlreturn).
- Между блоками `if`/`for`/`switch` и соседним кодом — пустая строка. Прижимать инструкцию к предыдущей строке (cuddle) можно только для `Lock()`, `RLock()` и `make(...)` (wsl). Пример:
  ```go
  mu.Lock()
  defer mu.Unlock()

  items := make([]T, 0, len(src))
  for _, x := range src {
      ...
  }
  ```
- В функциях с named returns всегда возвращай значения явно — `return val1, val2, err`, никаких naked return (nonakedreturn).

## Импорты

- Три группы, разделённые пустой строкой: stdlib → внешние модули → `a.yandex-team.ru/...` (importcheck).

## Именование

- Имена пакетов — нижний регистр, без `_`, единственное число (goodpackagenames).
- Sentinel errors — `ErrXxxNotFound`; типы ошибок — `XxxError` (errname).
- В рамках одной структуры используй единый стиль struct tag-ов: `json:"foo_bar"` без смешивания с camelCase (structtagcase).

## Ошибки

- Оборачивай через `%w` с контекстом действия: `fmt.Errorf("save base: %w", err)`, `"acquiring connection"`, `"scan row"` и т.п. (descriptiveerrors).
- Сравнивай ошибки через `errors.Is` / `errors.As`, не через `==` и не через type-assertion (errorlint).
- Не вызывай операцию, возвращающую ошибку, в инициализаторе `if`. Сначала выполни операцию, затем проверь `err` отдельным `if err != nil`.
- Если метод открыл tracing span, на каждом пути возврата внутренней ошибки сначала вызывай `span.RecordError(err)`. Записывай исходную ошибку до оборачивания. Между `span.RecordError(err)` и `return` оставляй пустую строку.

  ```go
  err := callbacks.Commit(ctx)
  if err != nil {
      span.RecordError(err)

      return fmt.Errorf("commit transaction: %w", err)
  }
  ```

## Корректность

- После HTTP-запроса закрывай `resp.Body` через `defer resp.Body.Close()` (bodyclose).
- Закрывай `*sql.Rows` / `*sql.Stmt` через `defer ... .Close()` (sqlclosecheck).
- Type assertion — только в форме `v, ok := x.(T)`, без однозначной `v := x.(T)` (forcetypeassert).
- Не оставляй присваивания, значение которых тут же перезаписывается (ineffassign).
- При literal-инициализации структуры перечисляй **все** поля (нулевые — явным нулём/`nil`). Для частичного заполнения используй конструктор/builder (exhaustivestruct).
- В `switch` по enum-типу перечисляй все значения или добавляй `default` (exhaustive).
- Неиспользуемые параметры функций именуй `_` (unusedargs).

## Запреты

- Никаких `fmt.Print*` в продакшен-коде — используй логгер (nofmtprint).
- Не используй deprecated API; если ругается на конкретный символ, ищи актуальную замену в том же пакете (SA1019).
- Не оставляй мёртвый код: неиспользуемые функции, типы, константы (U1000).
- Следи за цикломатической сложностью: длинные функции с глубокой вложенностью разбивай на хелперы (cyclop).

## Кастомные правила

- В монорепо есть проектные паттерны через ruleguard. Если сообщение линтера выглядит нестандартно — текст сообщения описывает требование (ruleguard).

## Как проверить

- `make lint-changed` — основной быстрый способ запустить линтеры только для локально изменённых файлов.
- `make lint-fix-changed` — то же, но сначала применяет автофиксы (wsl, nlreturn, staticcheck, импорты); остальное надо править руками.
- `ya make -t --style backend/apps/core` — полная проверка style для Core, когда она действительно нужна.
- `CGO_ENABLED=0` для `ya make` использовать **нельзя**.
